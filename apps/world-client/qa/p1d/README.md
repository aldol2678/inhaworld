## PC 자동과 수동 높음

PR #12에서 보고된 24.1 / 31.4 FPS와 동기 렌더 p95 40.5 / 36.7ms는 별도 문서 컨텍스트에서 각각 두 번 측정한 기록이다. 소스의 자동·수동 높음은 해당 시점에 모두 940×504, 4× MSAA, 9콜, 26,877삼각형이었다. 이번에는 각 빌드당 한 브라우저 문서·한 WebGL 컨텍스트에서 중앙 수로 서안 카메라를 고정하고 자동(A)·높음(B)을 ABBA–BAAB 순으로 실행했다. 두 선택 모두 실제 높음인 표본만 사용했다. DPR 1, 워밍업 12프레임, 선택별 총 RAF 160개와 동기 렌더 96개다. FPS는 1000/평균 RAF 간격, p95는 정렬한 표본의 최근접 상위 분위수다. 동기 시간에는 GPU 완료를 기다리는 단일 픽셀 readPixels가 들어간다. [기존 측정](https://github.com/aldol2678/inhaworld/blob/c4f3d938949b29acd178366592ccbf9330e0502b/apps/world-client/qa/p1bc/raw/performance.json) · [기준 8블록](raw/before-paired.json) · [P1D 8블록](raw/after-paired.json)

| 빌드 | 선택 | RAF FPS | RAF 중앙 ms | RAF p95 ms | 동기 중앙 ms | 동기 p95 ms | 콜 | 삼각형 | GL 버퍼 B |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| PR #12 | 자동 | 30.4 | 33.3 | 50.0 | 20.9 | 38.8 | 9 | 26,877 | 1,404,340 |

| P1D | 자동 | 29.0 | 33.3 | 66.6 | 21.1 | 39.0 | 9 | 27,101 | 1,407,574 |

자동과 수동의 기존 7.3 FPS 격차는 같은 크기로 재현되지 않았다. P1D에서 두 선택의 프레임 중앙값은 33.3ms였다. 자동의 RAF p95는 50.0→66.6ms, 동기 p95는 38.8→39.0ms로 측정됐다. 높은 단계의 PC 전반에 대한 속도 향상 판정은 보류한다. 같은 수로 장면의 높음은 드로우콜 9를 유지했고 포장 LOD 보강 등으로 224삼각형과 GL 버퍼 3,234바이트가 늘었다.

자동은 데스크톱·터치를 구분하고, 프레임 종료 시각 대신 브라우저가 전달하는 RAF 시각 사이의 간격을 센다. PC는 2초 창의 75백분위가 38ms를 넘는 상태가 두 창 이어질 때 하향한다. 터치에서는 29ms를 사용한다. 상향에는 빠른 창 5개가 필요하며, 하향 후 14초·상향 후 8초 동안 다시 전환하지 않는다. 실제 PC에서 키를 누르고 프레임에 54ms의 CPU 부하를 가했을 때 높음→중간, 해제 후 중간→높음이 관찰됐다. 중간 체류는 24.20초였으며 키를 누른 구간에 플레이어는 29.7 WU 이동했다. 모바일도 실제 지연 RAF에서 중간→낮음, 제어된 프레임 시퀀스에서 중간 복구를 검증했다.

별도 PC 실험은 네 차례 같은 장면에서 게임 RAF를 30Hz로 페이싱했다. 실제 브라우저 프레임 간격과 자동 단계 전환을 기록했고 순서는 PR #12 → P1D → P1D → PR #12였다. 각 230개 이상의 프레임 뒤 도달 단계는 `medium / high / high / medium`였다. 이 실험은 설정의 화질 유지 판단을 비교한다. ## 재실행

Node 24로 월드 클라이언트 디렉터리에서 `npm ci`, `npm run build`, `node tools/build-layout.mjs --check`, `npm test`를 실행한다. 독립 원장 재현은 `MOA_CAMPUS_DATA`에 승인된 포트 파일을 지정한다. 브라우저 시험은 Chromium 경로를 `CHROMIUM`에, 생성한 빈 디렉터리를 `WORLD_QA_DIR`에 지정한 뒤 `python -m pytest -q tests`로 실행한다. Python 재현 도구는 Playwright, Pillow, NumPy, SciPy, Matplotlib를 사용한다.

`qa/p1d/measure.py DIST JSON --mode paired` 또는 `--mode tiers`, `--mode sites`로 한 빌드를 측정한다. 두 dist를 각각 빌드한 뒤 `visual.py BEFORE AFTER OUT SCRATCH`, `interference.py BEFORE AFTER OUT`, `paced.py BEFORE AFTER OUT_JSON`으로 화면·공간·장기 판정을 재현할 수 있다. 실제 기상·태양 위치, 촬영 렌즈·좌표 및 공개 권한, 지상 벽과 나무의 상대 실측은 차기 현장 확인 항목이다.
